# Rime 0.3.58 编译负载隔离实验 · 2026-10-15

## 事实与假设

- 用户录屏确认：万象助手、Rime A/B、完整 Rime 都会显示短暂转圈；万象在键盘展开完成时已经能显示界面，Rime 还需要等待。
- Scripting 官方键盘规范要求 `keyboard.tsx`，调用 `CustomKeyboard.present()` 呈现界面。官方 `Script.runTS()` 明确运行时转译 TS/TSX，但**不说明键盘扩展是否每次都重新转译、或如何缓存编译产物**。
- 现有 JS `main()` 后的计时不包含宿主扩展激活、模块解析/编译、屏幕第一帧。不能把“编译是根因”写为已证实。

## 实验契约与安全边界

本轮只生成独立安装包 **Rime编译负载实验 0.3.58**，不修改原源码、正式 main、现有 0.3.57/latest.zip、历史 A/B 包。预览包不自动更新。

仅将原 `core/rime/T9BridgeAsset.ts` 中冻结的 25,254 字节 Lua 字符串变成原样 `core/rime/t9_bridge.lua` 文件（SHA256: `cd557d13d0db7f9ee402a26005966d5fed83c014d25bc539ebaab4684843d7f1`），并删去原 TypeScript 文件。唯一 TS 代码改变是 `T9BridgeRuntime.ts`：保持既有**校验正常时只读元数据的快速路径**；仅当配置失效需要修复时，从官方 `Script.directory` 读取 Lua 文件。资源缺失则报错并禁止写用户九键配置。Lua 本身、其他 TS、布局、键位、手势、Rime 初始化和 26 键/九键正常输入能力原则上不变，但 iOS 真机兼容性尚未验收。

测试契约：原 Rime 57 项、链接 6 项、逐文件 ZIP 与冻结 Lua SHA256 检查、静态依赖链检查，以及 4 项 VM 模拟（Lua 相等、正常九键快速路径、失效修复、资源缺失保护）。以上不代替 iOS 真机。

## 验收与决策

先确认预览版 26 键可以输入，再测试九键词语与候选；特别注意首次安装时 Script.directory 和资源文件在 iOS 键盘扩展下能否读取。用相同输入框、外部系统键盘触发进入 Scripting，录屏比较 0.3.57 与 0.3.58 的 T0（触发）、T1（脚本 UI 第一帧）、T2（输入生效）。若无明显提速即否决“提取 Lua 文件足够有效”的假设，不追加类似补丁。不能只在 Scripting 内部换脚本测试。

**重要：尚未确认 Scripting 原生编译缓存机制、真机能否读取 Lua 资源、也尚未测得任何启动毫秒收益。**

## 验收记录字段

每次记录：设备与 Scripting 版本、节能模式、键盘切换触发 T0、首帧 T1、首次输入回显 T2、是否复用扩展进程（未知则写未知）、26 键/九键是否完整可用。未经 iPhone 验收不得合并到正式分支。
